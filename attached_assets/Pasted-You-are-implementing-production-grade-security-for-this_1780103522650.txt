PART 1 — CONTENT SECURITY POLICY (CSP)
CSP is the most important browser security header. It tells the browser
exactly which resources are allowed to load — blocking XSS attacks even
if an attacker injects malicious code.
1a. Build the CSP header
Add to vercel.json headers section (replaces the generic /* header):
json{
  "key": "Content-Security-Policy",
  "value": "default-src 'self'; script-src 'self' 'wasm-unsafe-eval' https://plausible.io; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:; media-src 'self' blob:; worker-src 'self' blob:; child-src 'self' blob:; connect-src 'self' https://plausible.io https://api.exchangerate.host; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests;"
}
Explanation of each directive:

default-src 'self' → nothing loads by default unless explicitly allowed
script-src 'wasm-unsafe-eval' → REQUIRED for WASM (Tesseract, AVIF, pdf.js)
style-src 'unsafe-inline' → needed for CSS-in-JS libraries
img-src data: blob: → needed for image previews and tool output
worker-src blob: → needed for Web Workers (file processing)
connect-src → only Plausible analytics and exchange rate API
object-src 'none' → blocks Flash and plugins entirely
frame-ancestors 'none' → nobody can embed your site in an iframe (clickjacking)
upgrade-insecure-requests → forces HTTPS even if user types HTTP

1b. Test your CSP
After deploying, go to:

https://csp-evaluator.withgoogle.com — paste your CSP and check for weaknesses
https://observatory.mozilla.org — full security header audit

Target: A+ rating on Mozilla Observatory.
1c. CSP violation reporting (free)
Add a report-uri to catch violations in production without blocking users:
Content-Security-Policy-Report-Only: [same policy]; report-uri https://yourdomain.report-uri.com/r/d/csp/reportOnly
Sign up free at report-uri.com — you get notified of any CSP violation.
Start with Report-Only mode, fix all violations, then switch to enforcing.

3b. Sanitize everywhere user text touches the DOM
javascript// src/utils/sanitize.js
import DOMPurify from 'dompurify'

// For rendering user text as HTML (e.g. Markdown preview)
export const sanitizeHTML = (dirty) => {
  return DOMPurify.sanitize(dirty, {
    ALLOWED_TAGS: ['p', 'br', 'strong', 'em', 'ul', 'ol', 'li', 'h1', 'h2', 'h3', 'a', 'code', 'pre', 'blockquote'],
    ALLOWED_ATTR: ['href', 'target', 'rel'],
    ALLOW_DATA_ATTR: false,
    FORCE_BODY: true,
  })
}

// For rendering plain text — never use innerHTML, always use textContent
export const sanitizeText = (input) => {
  if (typeof input !== 'string') return ''
  return input
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#x27;')
}

// For filenames — strip dangerous characters
export const sanitizeFilename = (filename) => {
  if (typeof filename !== 'string') return 'file'
  return filename
    .replace(/[^a-zA-Z0-9.\-_\s]/g, '') // keep only safe chars
    .replace(/\s+/g, '-')               // spaces to dashes
    .replace(/\.{2,}/g, '.')            // no double dots (path traversal)
    .slice(0, 255)                       // max filename length
    || 'file'                            // fallback if empty after sanitize
}
3c. Audit every place user input touches the DOM
Search the entire codebase for these patterns and replace:

PART 6 — RATE LIMITING & ANTI-ABUSE
Even a client-side app can be abused. Large file processing can be used
to DoS the user's own browser, or bots can scrape the site.
6a. Client-side rate limiting
javascript// src/utils/rate-limit.js
class RateLimiter {
  constructor(maxRequests, windowMs) {
    this.maxRequests = maxRequests
    this.windowMs = windowMs
    this.requests = []
  }

  isAllowed() {
    const now = Date.now()
    // Remove old requests outside the window
    this.requests = this.requests.filter(time => now - time < this.windowMs)

    if (this.requests.length >= this.maxRequests) {
      return false
    }

    this.requests.push(now)
    return true
  }

  timeUntilReset() {
    if (this.requests.length === 0) return 0
    const oldest = Math.min(...this.requests)
    return this.windowMs - (Date.now() - oldest)
  }
}

// One limiter per tool — prevents repeated rapid processing
export const toolRateLimiter = new RateLimiter(
  10,       // max 10 operations
  60000     // per 60 seconds
)

// Usage in every tool:
if (!toolRateLimiter.isAllowed()) {
  const waitSeconds = Math.ceil(toolRateLimiter.timeUntilReset() / 1000)
  showError(`Too many operations. Please wait ${waitSeconds} seconds.`)
  return
}

6c. Zip bomb protection
Compressed files can be tiny but expand to gigabytes. Check after decompression:
javascript// When processing ZIP files or compressed formats
export const checkDecompressedSize = (decompressedBytes, originalBytes) => {
  const ratio = decompressedBytes / originalBytes
  if (ratio > 100) {
    // 100:1 compression ratio is suspicious
    throw new Error('File rejected: suspicious compression ratio detected.')
  }
  if (decompressedBytes > 500 * 1024 * 1024) {
    // Refuse anything that expands to > 500MB
    throw new Error('Decompressed file is too large to process safely.')
  }
}
