PART 1 — OVERFLOW & SCROLL FIXES
1a. Audit every overflow issue
Scan the entire codebase and every page for:

Any element causing horizontal scroll on mobile (overflow-x: auto on body is a symptom — find the cause)
Tool widgets that overflow their container on screens below 480px
Select dropdowns that are wider than the screen on mobile
Tables (unit lists, CSV viewer, results) that overflow horizontally — wrap in a scroll container
Long filenames or URLs that break layout — apply overflow: hidden; text-overflow: ellipsis; white-space: nowrap
Modals or panels that are wider than the viewport on mobile

Fix each overflow at its source. Never use overflow: hidden on body as a patch — find and fix the overflowing element.
1b. Contain scrollable areas properly
For any scrollable container (tool output areas, file lists, unit lists, CSV viewer):
css.scrollable-container {
  overflow-y: auto;
  overflow-x: hidden;
  max-height: 400px;
  /* Always define scroll containment explicitly */
  overscroll-behavior: contain; /* prevents page scroll chain */
}

PART 2 — RESPONSIVE PREMIUM
2a. Breakpoints — define and use consistently
Set up a consistent breakpoint system. Never use random pixel values:
css:root {
  /* Use these everywhere — never write a raw pixel breakpoint */
}

/* Breakpoints:
  mobile:  < 480px   (small phones)
  sm:      480px     (large phones)
  md:      768px     (tablets, landscape phones)
  lg:      1024px    (small laptops)
  xl:      1280px    (desktops)
  2xl:     1536px    (large screens)
*/
Audit the codebase and replace any arbitrary breakpoints (e.g. @media (max-width: 600px)) with the standardized ones.
2b. Mobile-first audit — every tool page
For every tool, test at 375px and 430px width (iPhone SE and iPhone 15 Pro). Fix:
Upload zone

Drop zone must stack vertically on mobile (icon above text)
Minimum height: 140px on mobile
Touch tap area must be the full zone — no small invisible click area

Controls & inputs

Input fields: full width on mobile (width: 100%)
Sliders (quality, size): must be at least 44px tall touch target — increase thumb size
Number inputs: use inputmode="numeric" for mobile keyboard
All inputs: font-size must be at least 16px on mobile to prevent iOS auto-zoom

Select dropdowns

On mobile, native <select> is acceptable and often better than custom dropdowns
If using custom dropdowns: they must open upward if near bottom of screen
Dropdown options must be at least 44px tall for touch

Buttons

All buttons: minimum 44px height on mobile (Apple HIG guideline)
Primary action button: full width on mobile
Button groups: stack vertically on mobile if they don't fit in one row

Tool layout

Two-column layouts (e.g. From/To in converters): stack to single column below md
Side-by-side comparison (before/after): stack vertically on mobile

File lists (Merge PDF, batch conversion)

Each file item: must have enough height to tap the remove button
Remove/reorder buttons: at least 44×44px touch area
Drag to reorder: add alternative up/down arrow buttons for mobile (drag & drop is unusable on mobile)

2c. Tablet layout (768px — 1024px)

Navigation: if the nav overflows at tablet width, convert to a hamburger or condensed layout
Tool grid on homepage: 2 columns at tablet (not 3 or 4)
Tool pages: content area max-width capped, centered — don't stretch full width on 1024px

2d. Large screen (1536px+)

Apply a max-width: 1400px; margin: 0 auto on the main content container
Tool pages: tool widget + content capped at max-width: 800px centered
Homepage grid: max 4 columns
Navigation: ensure it doesn't stretch awkwardly on ultrawide screens

2e. Touch interactions

Remove hover-only states that have no touch equivalent — they are invisible on mobile
Anywhere you use :hover for a tooltip or action, add a long-press or tap-to-reveal alternative
Drag & drop file upload: on touch devices, ensure the fallback "tap to browse" is always visible and large
For any drag-to-reorder list: add up/down buttons as touch alternative

2f. Images and assets

All images: max-width: 100% — never overflow their container
SVG icons: define explicit width and height in the SVG tag — do not rely on CSS alone
Tool preview thumbnails (PDF pages, image previews): constrain with object-fit: contain inside a fixed aspect-ratio box

PART 4 — SCREEN READER (ARIA) PREMIUM
4a. Semantic HTML first

Use the correct element for the job: <button> for actions, <a> for navigation, <nav>, <main>, <section>, <article>, <aside>, <header>, <footer>
Never use <div> or <span> for interactive elements without adding role and tabindex
Headings: one <h1> per page (the tool name), then <h2> for sections, <h3> for subsections — never skip levels

4b. Live regions — announce dynamic changes
When the tool state changes (processing starts, completes, or errors), announce it to screen readers:
html<!-- Add this once to the page -->
<div aria-live="polite" aria-atomic="true" class="sr-only" id="status-announcer"></div>
javascript// Utility function — use in every tool
const announce = (message) => {
  const announcer = document.getElementById('status-announcer');
  announcer.textContent = ''; // reset to re-trigger
  setTimeout(() => { announcer.textContent = message; }, 50);
}

// Usage:
announce('Compressing your PDF, please wait...');
announce('PDF compressed successfully. Ready to download.');
announce('Error: file is too large. Maximum size is 50MB.');

PART 5 — MOTION & REDUCED MOTION
Respect users who have vestibular disorders or motion sensitivity:
css/* Wrap ALL animations in this media query */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
Audit every CSS animation and transition — make sure they are wrapped or controlled by this query. The site must be fully usable with motion disabled.

PART 6 — TOUCH & MOBILE PREMIUM
Minimum touch targets
Every tappable element: minimum 44×44px. Implement with padding, not by changing visible size:
css.icon-btn {
  /* Visual size might be 20px icon */
  width: 20px;
  height: 20px;
  /* But touch area is 44×44px */
  padding: 12px;
  margin: -12px; /* compensate layout */
}
Prevent double-tap zoom on buttons
cssbutton, a, [role="button"] {
  touch-action: manipulation; /* disables double-tap zoom, keeps pinch-zoom */
}
Prevent text selection on interactive elements
cssbutton, [role="button"], .drop-zone {
  user-select: none;
  -webkit-user-select: none;
}
iOS-specific fixes

Add cursor: pointer on all interactive elements — required for click events on iOS Safari
Input fields: add autocomplete="off" on tool inputs to prevent iOS from suggesting weird values
For file download on iOS Safari: use a different approach than <a download> — iOS Safari doesn't always honor it. Use window.open(blobUrl) as fallback
