EXPANSION COMPLÈTE DU HUB D'OUTILS + CORRECTION DE TOUS LES BUGS

CONTEXTE
Le site tourne sur Oracle Cloud (backend ARM Ubuntu 24.04, 12GB RAM, 
Docker) + Vercel (frontend React/Vite). Le backend a accès à toutes 
les ressources système nécessaires — si une meilleure librairie existe 
pour un outil donné, on l'installe, même si elle n'est pas encore dans 
le Dockerfile actuel. L'objectif est la meilleure qualité possible pour 
chaque outil, pas de se limiter à ce qui est déjà installé.

Si une lib actuelle est sous-optimale pour une tâche, remplace-la par 
une meilleure — documente les changements de dépendances dans le 
Dockerfile pour qu'on puisse les installer sur Oracle.

PHASE 2 — IMPLÉMENTATION

Pour chaque outil de la Phase 1 :

1. Si l'outil existe déjà : vérifie qu'il utilise la meilleure lib 
   disponible et qu'il fonctionne correctement. Si une meilleure 
   alternative existe, migre vers elle.

2. Si l'outil est manquant : implémente-le complètement :
   - Route API backend (si traitement serveur nécessaire)
   - Page frontend React avec UI propre et cohérente
   - Branchement sur le composant <ToolLoadingState> existant

3. Choix des librairies — utilise toujours la MEILLEURE option 
   disponible, pas forcément ce qui est déjà installé :
   - Images → sharp (Node) ou Pillow (Python) selon la tâche
   - HEIC → pillow-heif Python (meilleure compatibilité que heic2any)
   - Background remove → rembg avec isnet-general-use (modèle actuel), 
     ou BiRefNet si disponible et meilleur
   - PDF manipulation → qpdf, ghostscript, pdf-lib selon l'opération
   - PDF→Document → pdfplumber Python pour l'extraction structurée
   - Document→PDF → LibreOffice headless (fidélité maximale)
   - OCR → Tesseract CLI (déjà prévu) ou EasyOCR si meilleure qualité
   - SVG vectorisation → potrace
   - Données → papaparse (CSV), fast-xml-parser (XML), js-yaml (YAML)
   - Si tu identifies une lib manquante qui améliorerait significativement 
     la qualité : ajoute-la au Dockerfile ET documente pourquoi dans un 
     commentaire

4. Pour les nouvelles dépendances système ou Python nécessaires :
   - Ajoute-les dans artifacts/api-server/Dockerfile
   - Documente chaque ajout avec un commentaire expliquant pourquoi
   - Si tu remplaces une lib existante par une meilleure, supprime 
     l'ancienne du Dockerfile

PHASE 3 — CORRECTION DES BUGS CONNUS

1. Background remover retourne 500 en production
   Cause probable : chemin du script bg_remove.py incorrect dans le 
   bundle esbuild compilé.
   Fix : utilise process.env.PYTHON_SCRIPTS_DIR ?? "/app/python" pour 
   tous les chemins vers des scripts Python, exactement comme déjà fait 
   pour pdf_extract.py dans convert.ts.
   Vérifie TOUS les fichiers de routes pour cette même erreur.

2. CORS absent sur les erreurs 500
   Ajoute un error handler global APRÈS toutes les routes dans 
   src/app.ts :
   
   app.use((err, req, res, next) => {
     const allowed = (process.env.FRONTEND_URL||'').split(',')
       .map(s => s.trim());
     const origin = req.headers.origin;
     if (origin && allowed.includes(origin)) {
       res.header('Access-Control-Allow-Origin', origin);
       res.header('Access-Control-Allow-Credentials', 'true');
     }
     logger.error({ err, url: req.url, method: req.method }, 
       'Unhandled error');
     res.status(500).json({ 
       error: true, 
       code: 'INTERNAL_ERROR', 
       message: err.message || 'An unexpected error occurred'
     });
   });

3. Variable PYTHON_SCRIPTS_DIR manquante
   Ajoute dans .env.example : PYTHON_SCRIPTS_DIR=/app/python
