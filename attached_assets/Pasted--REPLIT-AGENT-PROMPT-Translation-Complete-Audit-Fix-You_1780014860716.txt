## STEP 4 — SPECIAL CASE: ARRAYS AND OBJECTS WITH LABELS

The unit converter and currency converter use arrays of objects with labels. These are often missed because they look like data, not UI text. Fix this pattern:

### WRONG — hardcoded labels in data array:
```javascript
const LENGTH_UNITS = [
  { label: "Kilometer", value: "km", factor: 1000 },
  { label: "Meter", value: "m", factor: 1 },
  { label: "Mile", value: "mi", factor: 1609.34 },
]

// Rendered as:
{LENGTH_UNITS.map(unit => (
  <option value={unit.value}>{unit.label}</option>
))}
```

### RIGHT — translation keys in data, labels resolved at render time:
```javascript
const LENGTH_UNITS = [
  { labelKey: "unit_converter.units.kilometer", value: "km", factor: 1000 },
  { labelKey: "unit_converter.units.meter", value: "m", factor: 1 },
  { labelKey: "unit_converter.units.mile", value: "mi", factor: 1609.34 },
]

// Rendered as:
{LENGTH_UNITS.map(unit => (
  <option value={unit.value}>{t(unit.labelKey)}</option>
))}
```

Apply this pattern to EVERY array of options across the entire codebase:
- Unit categories and unit names (Unit Converter)
- Currency names (Currency Converter)
- Image format options (Image tools)
- Compression level options (Compress tools)
- PDF permission options (Protect PDF)
- Error correction levels (QR Code)
- Any other select/dropdown data
